# v0.2 사전 검증: MacBook 설치와 네이티브 기본 기능

검증일: **2026-09-12**

Apple M5 Max MacBook Pro에 일반 Pointory 앱을 설치하고, 같은 소스의 별도
검증 앱으로 네이티브 WKWebView 기본 기능을 검사했습니다. 첫 실행은 **11개
통과**, 재실행은 **12개 통과·1개 실패**였습니다. 실패 항목은 검증 앱의 화면
기록 권한 검사입니다. 실제 마우스 조작과 전체 화면·판서의 웹 전송은 아직
완료하지 않았으므로 전체 사용 검증 통과로 판정하지 않습니다.

[Windows → Mac 공유 검증](0.2-windows-share-mac.ko.md) ·
[이전 Mac mini 음성 모델 검증](0.2-macos-models.ko.md)

## 설치 환경

| 항목 | 확인 결과 |
| --- | --- |
| 장비·OS | MacBook Pro, Apple M5 Max, macOS 26.3.1 (a) |
| 내장 Retina 화면 | 논리 1800 × 1169, 실제 3600 × 2338, 배율 2 |
| 일반 앱 | 개발용 DMG에서 설치한 `/Applications/Pointory.app` |
| 앱 소스 | `97ea1ee9471af262f0216d2b2d624a60a5b88dd2` |
| 기본 설정 | 한국어, Apple SD Gothic Neo, 설정 글자 14px, 가로 툴바, 내장 화면 |
| 일반 앱 창 | 툴바 766 × 64, 설정 520 × 700, 화면 크기에 맞는 오버레이 확인 |
| 검사 앱 | 별도 `Pointory-Check/native-97ea1ee/Pointory-validation.app` |
| 설치 앱 무결성 | `codesign` 검증 통과; Developer ID 서명·공증 검사는 아님 |

설치에 사용한 DMG의 SHA-256:

```text
6b68559be1acf55501ef90d3c8e9d847a1d052b3b9847e5cef2aecb36b667adf
```

네이티브 자동 검사는 일반 앱을 정상 종료한 뒤 별도 설정 프로필로 실행하고,
종료 후 일반 앱을 다시 열었습니다. 검사용 글꼴 크기·테마·굵기·툴바 순서는
사용자 프로필과 분리했으며 macOS 권한 데이터베이스(TCC)는 수정하지 않았습니다.
일반 앱의 한국어·Apple SD Gothic Neo·14px·가로 툴바·펜 굵기 4 설정 유지도
확인했습니다. 이후 원격 화면 제어 준비를 위해 일반 앱을 정상 종료하고
macOS 공유 설정을 열었습니다. 원격 화면 공유에 대한 사용자 승인을 기다리는
상태이며 앱과 사용자 프로필은 보존했습니다.

## 네이티브 검사 결과

| 범위 | 결과와 한계 |
| --- | --- |
| 화면·브랜드 | Retina 배율과 화면 크기, Pointory 이름·심볼 이미지 디코딩 확인 |
| 툴바 | 가로·세로 전환, 패널, 사용자 지정 굵기 유지 확인 |
| 설정 | 도킹, 시스템 글꼴 679개 조회, 선택 글꼴 적용, 테마·툴바 항목 변경 확인 |
| 설정 글자 크기 | 20px 적용, 저장, 앱 재실행 후 유지 확인 |
| 텍스트 | WKWebView에 합성 입력을 전달해 한국어 텍스트 생성 확인 |
| 판서·내보내기 | 합성 판서의 실행 취소·다시 실행, 판서 레이어 PNG와 GIF 저장 확인 |
| 스포트라이트 | 켜기·끄기·재시작과 WebView ESC 이벤트 확인; 확대는 끈 상태 |
| 공유 서버 | 시작, 주소·QR 생성, 중지 후 상태 초기화 확인; 외부 수신 검사는 아님 |
| 전체 화면 캡처 | 두 번째 실행에서 검증 앱의 화면 기록 권한 부족으로 실패 |

첫 실행은 기본 검사 11개가 모두 통과했습니다. 두 번째 실행은 같은 기본
검사와 재실행 후 설정 유지까지 12개가 통과했고, 추가한 전체 화면 캡처
검사 1개가 실패했습니다. 프로세스 종료 코드는 두 실행 모두 0이었으나,
두 번째 보고서와 종합 보고서의 상태는 `failed`입니다.

저장한 PNG는 3600 × 2338 RGBA이며, 직접 작성한 한국어 테스트 문구와 파란
선이 보이는 것을 확인했습니다. GIF는 960 × 623, 2개 프레임으로 디코딩됐습니다.

사용자는 일반 설치 앱의 화면 기록 허용과 재실행을 완료했다고 알려주었습니다.
위 실패는 **다른 경로의 검증 앱**에서 발생했으므로 일반 설치 앱의 승인이
실패했다는 증거로 볼 수 없습니다. 일반 앱이 실제 화면을 캡처할 수 있는지는
별도 확인이 필요합니다. 판서 레이어 PNG·GIF 성공도 전체 모니터 캡처의
권한·내용 검증을 대신하지 않습니다.

## 같은 LAN의 Windows 공유 서버 접속

Windows Rust 공유 fixture에 Mac Python HTTP 클라이언트가 VPN·SSH 터널
없이 직접 접속했습니다. 페이지 `200`, 공개 README 11,484 bytes 다운로드와
SHA-256 일치, 서로 다른 합성 JPEG 프레임 3개 수신을 확인했습니다. 검사
서버는 종료했습니다.

이 결과는 해당 LAN에서 Windows → Mac 자료·이미지 HTTP 전송이 가능하다는
증거입니다. Mac 브라우저 화면 표시나 실제 데스크톱·판서 전송은 검사하지
않았습니다. 전날 VPN 경로의 시간 초과와는 다른 네트워크·장비에서 얻은
결과이며, 이전 실패 원인을 규명하거나 해결한 결과는 아닙니다.

## 남은 실제 사용 확인

- 일반 설치 앱의 화면 기록 권한으로 전체 화면을 캡처하고 판서가 포함되는지 확인.
- 실제 마우스·키보드로 판서, 클릭 위치의 텍스트 입력과 한국어 IME, 전역 ESC 확인.
- 브라우저에서 실제 판서 화면 수신과 공유 중지 동작 확인.
- 마이크 자막, 화면 확대, 다중 모니터와 여러 수강생 동시 접속 확인.

근거는 설치 요약 `setup.json`, 직접 LAN 결과 `windows-lan-http.json`,
네이티브 종합 `latest-native.json` 및 실행별 `run-1.json`·`run-2.json`입니다.
계정·주소·공유 토큰·개인 경로가 포함된 원본 보고서와 캡처는 공개 문서에
첨부하지 않았습니다.
