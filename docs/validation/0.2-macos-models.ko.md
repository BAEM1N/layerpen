# macOS 음성 엔진·모델 준비 검증 — 2026-09-11

Apple M4 Mac mini에서 최신 음성 엔진 설치, Whisper tiny 모델 다운로드, 앱 번들의 오프라인 파일 음성 인식을 확인했습니다. 일반 앱·검증 앱·개발용 DMG도 다시 빌드했습니다. Mac은 로그인 화면 상태였으므로 이번 결과에는 최신 툴바의 실제 표시·클릭, 설정 버튼을 통한 설치, 실제 마이크 녹음이 포함되지 않습니다.

모델 다운로드는 설정 버튼이 호출하는 동일한 Python helper에 요청을 전달해 실행했습니다. 네이티브 설정 창에서 버튼을 누른 검사는 아닙니다. 음성 파일에는 직접 작성한 테스트 문장을 사용했으며, 파일 재생을 실제 시간에 맞춰 전달했습니다. 따라서 전체 실행 시간은 순수 추론 시간이나 수업 환경의 인식 정확도 지표가 아닙니다. 원음·화면·마이크를 새로 수집하지 않았고 API 키도 사용하지 않았습니다.

번들 사전 검사의 `stt_model_inference`는 해당 검사기가 추론을 수행하지 않아 제외된 항목입니다. 추론 자체는 별도의 파일 검사로 확인했습니다. 입력 마이크 목록이 비어 있고, Apple GPU/Neural Engine 경로는 구현되지 않아 실제 녹음과 Apple 가속은 확인하지 못했습니다.

## 발견한 문제와 보완

- **Finder 실행 시 Python 탐색:** 시스템 Python은 3.9.6이었습니다. Mac 앱은 호환되는 관리·레거시 환경, PATH, Homebrew와 Python.org의 일반 설치 경로를 순서대로 검사하고 Python 3.10 이상을 선택하도록 보완했습니다. 명시적으로 지정한 Python은 계속 우선합니다. 탐색 순서·버전 제외는 자동 검사로 확인했으며 Finder에서 실제 실행한 결과는 아닙니다.
- **오래된 관리 환경 복구:** 별도 테스트 폴더에 실제 Python 3.9.6 가상환경을 만들고 설치 helper로 3.13.15 환경으로 복구했습니다. 기존 확인용 파일과 모델 가중치의 해시가 유지됐습니다. 관리 경로의 실행 링크만 교체하고 가상환경을 갱신하며 모델 캐시는 지우지 않습니다.
- **앱 번들 보호:** Python worker를 `-B`로 실행해 서명된 앱 리소스 옆에 `__pycache__`를 만들지 않습니다. 번들 모델 조회·파일 인식 후에도 리소스 해시와 ad hoc 서명 검사가 통과했습니다.
- **Mac 임시 경로 검사:** `/var`가 `/private/var`로 해석되는 환경에 맞춰 테스트의 예상 경로를 정규화했습니다. 설치 동작의 실패가 아니라 테스트 경로 비교의 오류였습니다.

Python 3.10 이상 자체를 설치하는 기능은 제공하지 않습니다. 새 환경에서 사용할 호환 Python이 전혀 없으면 먼저 Python을 설치해야 합니다. 현재 확인한 Mac에는 음성 엔진과 tiny 모델을 준비해 두었습니다.

## 현장에 남은 확인

Mac 바탕화면까지 로그인한 뒤 `~/Desktop/Pointory-Check`의 최신 준비 앱과 실행기로 확인합니다. 이전 준비 빌드와 사용자의 수동 검사 설정은 보존합니다.

1. 새 Lucide 아이콘과 Pointory 심볼, 가로·세로 툴바, 설정 도킹과 글꼴 표시.
2. 설정에서 모델 다운로드·취소·재시도, 창 닫기·다시 열기의 실제 UI 동작.
3. 마이크 연결·권한 승인 후 실제 음성 자막과 중지·재시작.
4. DMG에서 설치한 앱의 실행, 화면 기록 권한과 전체 모니터 캡처.

이번 DMG는 개발용 ad hoc 서명입니다. Developer ID 서명·공증·Mac App Store 배포나 Gatekeeper 허용 검증 완료를 뜻하지 않습니다. Retina·여러 모니터·Apple GPU/Neural Engine·Mac 시스템 오디오는 기존 후속 과제로 남아 있습니다.
