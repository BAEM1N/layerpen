# Pointory v0.2 준비: macOS 실기 검증 — 2026-09-10

Apple Silicon Mac에서 **기본 필기·툴바·내보내기의 네이티브 시나리오 9개를 검증했습니다.** 이는 재부팅 전 개발 빌드의 결과입니다. 이후 추가한 설정 글꼴·크기 기능은 브라우저에서 검증했으며, 최신 변경을 반영한 Mac 앱의 재실행은 아직 검증하지 못했습니다. 화면 기록 권한을 승인한 전체 화면 캡처, 실제 마이크 입력, Apple GPU/ANE 가속도 미검증입니다. 이 문서는 v0.2 출시를 준비하는 개발 검증 기록이며, 정식 Mac 릴리스 완료를 뜻하지 않습니다.

## 환경과 자동 검사

| 항목 | 확인한 환경 |
| --- | --- |
| 하드웨어 | Mac mini, Apple M4, GPU 10코어, 메모리 16 GB |
| 운영체제 | macOS 26.2, 빌드 25C56, arm64 |
| 화면 | 단일 1920×1080, 배율 1 |
| 개발 도구 | Node.js 22.23.2, Rust 1.98.1, Python 3.13 |
| Rust 검사 | Mac·Windows 각각 39개 통과, 수동 fixture 1개 제외 |
| UI·STT 검사 | JavaScript UI 29개, Python STT 18개 통과 |
| 자동 검사 합계 | 검사 종류별 86개. OS별 반복 실행을 중복 합산하지 않음 |
| 별도 브라우저 검사 | 설정 글꼴·크기: 4언어 × 5크기 × 2너비, 40조합 통과 |
| 앱 번들 | 검증용 코드가 없는 일반 arm64 `.app` 생성·구성 확인 완료 |
| DMG | 최신 메인 스레드 잠금 수정 포함: 생성·무결성·읽기 전용 마운트·ad hoc 서명 검사 통과 |
| Windows 회귀 빌드 | 최신 변경을 반영한 NSIS 설치 파일 빌드 통과 |

자동 검사 수에는 네이티브 UI 시나리오를 별도로 더하지 않습니다. 이번 결과를 Intel Mac, 이전 macOS, Retina 또는 여러 모니터 환경의 실기 검증으로 확대해 해석하지 않습니다.

## 재부팅 전 네이티브 WKWebView 시나리오 9개

실제 Mac 앱의 WKWebView에서 이벤트와 명령을 실행하고 상태·창·파일 결과를 확인했습니다. 별도 웹 브라우저의 목업 테스트가 아닙니다. 다만 합성 포인터 이벤트와 텍스트 값 입력을 사용하므로 실제 키보드의 한글 IME 조합, 물리 마우스의 모든 동작을 검증한 것은 아닙니다.

이 9개는 설정 글꼴·크기 추가와 메인 스레드 잠금 수정 전 결과이며, 최신 변경 전체의 재검증 결과로 간주하지 않습니다. 재부팅 후 로그인된 데스크톱 세션이 없어 새 10번째 설정 시나리오와 최신 앱 실행을 확인하지 못했습니다.

| 시나리오 | 확인 결과 |
| --- | --- |
| 1. 실행과 브랜드 | Pointory 창 제목과 설정 로고 표시 |
| 2. 가로 툴바 | 660×64, 기본 컨트롤 15개, 패널 확장, 도형·색상·굵기 선택, Escape 동작 |
| 3. 세로 전환 | 64×660으로 전환하며 선택한 굵기 유지 |
| 4. 설정과 글꼴 | 툴바 옆 설정 도킹, 시스템 글꼴 항목 668개, Apple SD Gothic Neo 선택, teal 테마 적용 |
| 5. 텍스트 | 합성 PointerEvent로 위치 선택 후 textarea에 한국어 문자열을 넣고 텍스트 획으로 확정 |
| 6. 필기 편집과 PNG | 필기 실행 취소·다시 실행, 투명 필기 PNG 내보내기 |
| 7. GIF | 실제 GIF 파일 생성 |
| 8. 스포트라이트 | 켜기·끄기와 주변 어둡게 처리. Mac에서는 원형 실시간 확대를 제공하지 않음 |
| 9. 자료 공유 | localhost 서버 시작, QR 표시, 서버 중지 |

투명 PNG와 GIF 생성은 다른 앱의 화면 내용이 포함되는 전체 모니터 캡처 성공과 구분합니다. localhost 공유 시작·종료는 수강생의 다른 기기 접속이나 실제 모니터 스트리밍을 검증한 결과가 아닙니다.

## 설정 글꼴·크기 추가 검증

기존 텍스트 글꼴 선택을 설정 창 전체에도 적용하고, 설정 글자 크기를 12 / 14 / 16 / 18 / 20 px에서 고르도록 추가했습니다. 기본값은 14 px입니다. 시스템 글꼴과 가져온 TTF를 같은 선택기로 사용하며, 설정 글자 크기를 바꾸어도 펜 굵기·캔버스 텍스트 크기·툴바 크기는 유지됩니다. [한국어 사용법](../../Wiki/KR/04-text-fonts.md) · [English guide](../../Wiki/EN/04-text-fonts.md)

이 기능은 브라우저에서 4언어 × 5크기 × 2너비, 총 40조합을 검증했고 한국어·영어의 실제 FontFace 로드도 확인했습니다. 저장·기본값·허용 크기 검사는 Rust 자동 검사에 포함합니다. Mac의 실제 WKWebView에서 새 설정 시나리오를 실행하는 검증은 대기 중입니다.

## 앱·DMG 구성과 서명

최신 메인 스레드 잠금 수정까지 포함한 일반 arm64 `.app`과 DMG를 빌드했습니다. 최종 DMG의 `hdiutil verify` 체크섬과 읽기 전용 마운트를 통과했고, arm64 Pointory 앱·Applications 바로가기·Info.plist·검증용 실행 코드 제외를 확인했습니다. Windows에서도 같은 최신 변경을 반영한 NSIS 설치 파일 빌드가 통과했습니다.

`APPLE_SIGNING_IDENTITY=-`를 적용한 최종 앱은 `codesign --verify --deep --strict`가 통과했으며 `Signature=adhoc`, `SealedResources`의 리소스 16개를 확인했습니다. 초기 링크 단계의 서명만 남아 리소스 서명이 누락되던 문제를 해결한 결과입니다. Developer ID 서명과 공증은 없습니다.

빌드·파일·서명 검사는 완료했지만 **DMG에서 설치한 앱의 실행은 아직 검증하지 못했습니다.** 재부팅 전 네이티브 시나리오 9개를 최신 빌드의 실행 결과로 간주하지 않습니다.

Mac 저장소 루트에서 개발용 미리보기 빌드를 생성하는 명령은 다음과 같습니다.

```sh
CI=true APPLE_SIGNING_IDENTITY=- npm exec -- tauri build --bundles app,dmg -- --locked
```

Tauri는 `APPLE_SIGNING_IDENTITY` 또는 설정의 서명 식별자로 `-`를 사용해 ad hoc 서명을 지정할 수 있다고 안내합니다. 이 서명은 Developer ID 서명이나 공증을 대신하지 않으며, 다운로드한 앱의 Gatekeeper 허용 여부는 별도 확인 사항입니다. [Tauri 공식 ad hoc 서명 안내](https://v2.tauri.app/distribute/sign/macos/#ad-hoc-signing)

## 발견한 문제와 수정

### 메뉴 막대 아래로 밀리는 오버레이

실제 Core Graphics 창 위치에서 오버레이의 Y 좌표가 30으로 잡혀 화면 위쪽과 어긋나는 문제를 확인했습니다. Mac 네이티브 창 레벨과 AppKit 프레임 배치를 조정한 뒤 **오버레이 `(0, 0, 1920, 1080)`**, 툴바 시작 위치 `(630, 24)`를 확인했습니다.

AppKit 창 배치는 화면 좌표의 프레임과 자동 위치 제약을 다룹니다. Apple은 `constrainFrameRect(_:to:)`가 화면에 맞추어 창 프레임을 조정한다고 설명합니다. 이번 30픽셀 차이는 그 문서만으로 추정한 결과가 아니라 실제 창 위치를 수정 전후로 측정한 결과입니다. [Apple NSWindow 프레임 제약](https://developer.apple.com/documentation/appkit/nswindow/constrainframerect%28_%3Ato%3A%29)

### Retina·보조 모니터 좌표 변환

Tauri에서 얻는 배율 적용 좌표와 캡처 모니터 좌표를 그대로 비교하던 결함을 정적 검토로 발견해 수정했습니다. Mac에서 논리 좌표로 변환하고, 배율 2 및 주 모니터의 왼쪽·위쪽 화면 좌표를 다루는 테스트를 추가했습니다. **이번 실기는 배율 1의 단일 화면이므로 Retina·혼합 DPI·보조 모니터는 여전히 미검증입니다.** Apple의 `backingScaleFactor` 설명도 화면 공간과 backing 픽셀 사이의 비율을 구분합니다. [Apple NSScreen 배율](https://developer.apple.com/documentation/appkit/nsscreen/backingscalefactor)

### Mac 마이크 장치 ID와 권한 설명

설정의 문자열 장치 ID를 Mac 오디오 경로가 요구하는 정수 ID로 변환하도록 수정하고 회귀 검사에 포함했습니다. `.app`의 Info.plist에는 실시간 자막용 마이크 접근 이유인 `NSMicrophoneUsageDescription`을 추가했습니다. Apple은 마이크 API를 사용하는 앱에 이 설명 키를 요구합니다. 설명 키가 있다는 사실과 사용자의 승인·실제 녹음 성공은 별도 확인 사항입니다. [Apple 마이크 권한 설명](https://developer.apple.com/documentation/bundleresources/information-property-list/nsmicrophoneusagedescription), [macOS 미디어 접근 승인](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos)

### 화면 기록 미승인 처리

화면 기록 권한을 승인하지 않은 실제 Mac에서 Core Graphics 권한 확인 경로를 실행했습니다. 정상 macOS 권한 요청이 표시되고 앱이 권한 필요 오류를 명시적으로 반환하는 것을 확인했습니다. 권한 없이 다른 앱의 내용이 누락된 이미지를 캡처 성공으로 처리하지 않습니다.

이번 검증은 기본 기능 범위로 마쳤으며 화면 기록 권한은 승인하지 않았습니다. 권한 승인 후 전체 모니터 캡처나 실시간 화면 전송이 성공한 결과는 아닙니다.

## 오디오·화면 권한·가속 상태

- 이 Mac에서 감지된 입력 장치 목록은 `[]`였습니다. 사용할 마이크가 없어 실제 녹음, 장치 변경, 중지·재시작과 음성 자막을 검증하지 못했습니다.
- CPU 실행 경로 탐지는 정상입니다. 실제 마이크를 통한 인식 성공이나 성능 벤치마크를 뜻하지 않습니다.
- Apple GPU/Neural Engine 실행 경로는 아직 구현하지 않았습니다. M4의 GPU가 존재한다는 사실만으로 앱의 가속 기능이 활성화된 것은 아닙니다.
- 현재 SoundCard 경로의 Mac 시스템 오디오는 지원하지 않습니다. 마이크 권한을 허용해도 시스템 오디오 지원이 추가되지는 않습니다.
- 화면 기록 미승인 상태의 정상 권한 요청·명시적 오류 반환을 확인했습니다. 권한 승인 후 다른 앱의 내용까지 포함하는 전체 화면 캡처와 실시간 공유는 후속 검증이 필요합니다. Apple은 화면 캡처 권한 확인과 요청 API를 구분합니다. [Apple 화면 캡처 권한 안내](https://developer.apple.com/forums/thread/683860?answerId=684400022)

## 남은 실기·배포 검증

- 로그인된 Mac 데스크톱에서 최신 변경을 반영한 앱 실행과 새 설정 글꼴·크기 시나리오 재검증.
- 화면 기록 권한 승인 후 재시도와 실행 중 권한 변경, 실제 앱 창이 포함된 PNG·영역 확대·LAN 화면 전송.
- 실제 마이크 연결 후 장치 선택, 녹음·중지·재시작, CPU 인식과 클라우드 제공자 연결.
- 실제 한글 IME 입력·조합·확정, TTF 직접 가져오기, 전역 단축키와 클릭 통과의 실제 입력 동작.
- Retina·여러 모니터·혼합 DPI, 전체화면 앱과 Spaces, Intel Mac.
- DMG의 실제 설치·실행, Developer ID 서명·공증, Gatekeeper와 Mac App Store 배포 검토.

현재 `macOSPrivateApi` 설정을 포함한 스토어 적합성 검토도 남아 있습니다. `.app` 빌드와 이 문서의 기능 검증은 서명·공증 또는 스토어 심사 통과를 의미하지 않습니다.
