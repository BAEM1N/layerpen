# v0.2 사전 검증: Windows 공유 서버와 Mac 브라우저

검증일: **2026-09-11**

Windows의 실제 Pointory Rust 공유 서버에 Mac 브라우저를 연결해 파일
다운로드와 변경되는 예제 프레임 표시를 확인했습니다. 성공한 연결은 임시
SSH 역방향 포워딩을 거친 경로입니다. Mac에서 Windows VPN 주소로 직접
접속한 HTTP 요청은 시간 초과됐으며, 직접 연결 문제는 아직 해결되지 않았습니다.

**2026-09-12 후속 검사:** 다른 MacBook과 같은 LAN에서 Windows Rust 공유
서버에 직접 HTTP 접속했습니다. 페이지·파일·합성 프레임 수신은 성공했으며,
이 후속 검사는 Mac Python HTTP 클라이언트로 수행했습니다. 브라우저나 실제
화면 전송 검사와 구분하며, 아래 전날 VPN 검사 결과를 대체하지 않습니다.

## 검증 환경과 연결 경로

- Windows의 Wi-Fi 네트워크와 Mac의 LAN은 서로 달랐습니다.
- Windows에서 WireGuard가 활성화된 상태로 Mac에 SSH 접속할 수 있었습니다.
- Mac에서 Windows VPN 주소로 보낸 직접 HTTP 요청은 Rust 공유 fixture에서
  두 차례, 별도의 Node HTTP 진단 서버에서 한 차례 시간 초과됐습니다.
- Windows 자체에서 공유 서버에 보낸 HTTP 요청은 `200`이었습니다.
- 방화벽 허용 규칙은 확인했습니다. 방화벽 적용 범위, VPN 게이트웨이 또는
  네트워크 정책 가운데 어느 부분이 직접 접속을 막는지는 확정하지 못했습니다.

Windows에서 시작한 SSH 연결에 임시 역방향 포워딩을 설정하고, Mac 쪽
수신 주소를 loopback으로 제한해 브라우저 검사를 진행했습니다. Mac 브라우저의
HTTP 요청이 이 중계 경로를 통해 Windows의 실제 Rust 서버에 도달했습니다.
이 결과는 수강생 기기에서 강사 PC의 공유 포트로 직접 접속할 수 있다는
증거로 사용할 수 없습니다. SSH와 HTTP는 접속 방향과 대상 포트가 다르므로
각 경로를 따로 확인해야 합니다.

## 브라우저 검사 결과

Mac M4의 **Chromium headless 151**에서 실제 수강생 페이지와 제품의
`share-viewer.js`를 사용했습니다.

| 검사 | 결과 |
| --- | --- |
| 페이지 제목과 실제 DOM | Pointory 수업 자료 페이지 표시 |
| 실제 브라우저 파일 다운로드 | 공개 README, 11,484 bytes |
| 파일 무결성 | 브라우저 다운로드와 Windows 원본의 SHA-256 일치 |
| JPEG 응답 | `200`, `image/jpeg`, `Cache-Control: no-store` |
| 브라우저 이미지 디코딩 | 640 × 360 |
| 표시 프레임 변경 | 2.253초 동안 채집한 5개 프레임이 모두 다름 |
| 브라우저 JavaScript 오류 | 0개 |
| 접속 토큰 없는 요청 | `404` |
| 존재하지 않는 파일 요청 | `404` |

검사한 README의 SHA-256:

```text
e12c633ee57dbadfad9820c56087fcc54c2f3e306ecede8769e30c822d66daf8
```

프레임 검사는 브라우저가 표시하는 `#live` 이미지를 디코딩한 뒤 canvas로
내보내 SHA-256을 비교했습니다. HTTP 응답 파일을 따로 가져오는 검사에 더해,
제품의 viewer가 새 프레임을 받아 실제 이미지 요소를 갱신하는 경로를 확인했습니다.
최종 브라우저 캡처 이미지의 표시 상태를 직접 확인했고, 다운로드 파일의
SHA-256을 Windows 원본과 다시 비교해 일치를 확인했습니다.

## 화면 캡처를 사용하지 않는 fixture

수동 테스트인 `sharing::tests::browser_fixture`에 고정 포트 선택과 동적
예제 프레임 옵션을 추가했습니다. 변경은 `#[cfg(test)]` 모듈에 한정되며
제품의 공유 서버 로직은 변경하지 않았습니다.

- 동적 프레임은 테스트 코드가 직접 생성한 RGB 패턴입니다. 움직이는 띠와
  프레임 번호를 나타내는 패턴을 500ms마다 JPEG로 인코딩합니다.
- 동적 모드에서는 화면 캡처 API, 외부 이미지, 개인 자료를 사용하지 않습니다.
  다운로드용 자료는 프로젝트의 공개 README입니다.
- 기존 정적 예제 모드, 사설 IPv4 검사, 5~300초 실행 제한은 유지됩니다.
- Rust 공유 테스트 **4개 통과**, 수동 브라우저 fixture **1개 기본 실행 제외**를
  확인했습니다. 이미지 생성 테스트는 JPEG 디코딩, 크기, 프레임 차이와 결정성을
  검사합니다.

## 검사 종료 확인

검사용 Windows Rust 서버와 Node 진단 서버가 모두 종료된 것을 확인했습니다.
SSH 중계 도우미도 종료했고, Mac의 임시 loopback 접속 지점에 후속 HTTP
요청을 보내 연결 거부를 확인했습니다. 검증용 서버나 중계 연결을 계속
실행하는 상태로 남기지 않았습니다.

## 남은 검증

이번 결과는 원격 headless 브라우저의 HTTP·파일·이미지 갱신 검사입니다.
로그인한 Mac 데스크톱을 조작한 GUI 검사나 실제 모니터 캡처 검사는 포함하지
않습니다. 공유할 Windows 모니터를 선택하고 준비한 뒤 실제 판서와 열린 창을
전송하는 검증, 수업 네트워크에서 수강생 기기의 직접 TCP 접속, 여러 수강생의
동시 접속 부하 검증이 남아 있습니다. 이 방향에서 Mac은 웹 수신기이며
Mac 화면 캡처 권한을 검사하는 것이 아닙니다.

VPN 사용 여부만으로 주소를 선택하지 않고, **수강생 기기에서 강사 PC의
해당 HTTP 포트에 접속할 수 있으며 학교·조직 정책이 허용하는 IPv4 경로**인지
확인해야 합니다. 이번 직접 HTTP 시간 초과의 원인은 추가 네트워크 진단이
필요합니다.

## 2026-09-12 후속: 같은 LAN의 직접 HTTP 접속

Windows와 Apple M5 Max MacBook Pro(macOS 26.3.1 (a))를 같은 내부망에서
연결했습니다. Mac Python HTTP 클라이언트가 Windows의 실제 Rust 공유
fixture에 직접 접속했으며 VPN이나 SSH 터널은 사용하지 않았습니다.

| 검사 | 결과 |
| --- | --- |
| 공유 페이지 | HTTP `200` |
| 공개 README 다운로드 | 11,484 bytes, 위 Windows 원본 SHA-256과 일치 |
| 합성 JPEG 프레임 | 수신한 3개 프레임의 SHA-256이 모두 다름 |
| 검사 서버 | 종료 확인 |

이 검사는 해당 LAN의 직접 HTTP 접속과 파일·이미지 전송을 확인했습니다.
클라이언트가 Python이므로 Mac 브라우저의 DOM·JavaScript·화면 표시는 검사하지
않았습니다. 프레임은 직접 작성한 합성 이미지이며 Windows의 실제 바탕화면이나
판서를 캡처한 것이 아닙니다.

전날 VPN 시간 초과와는 다른 환경에서의 성공입니다. 기존 VPN·방화벽 경로의
실패 원인을 규명하거나 해결했다는 뜻은 아닙니다. Mac 설치와 네이티브 기본
기능의 별도 결과는 [MacBook 검증](0.2-macbook.ko.md)에 기록했습니다.
